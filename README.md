# معرض رواد الاعتماد للسيارات

> **الموقع الرسمي للمعرض:** https://ruwwadaletemad.com/
> هذا المستودع يستضيف **بوابة الموظفين** فقط (`index.html`) وتحتها نظام إدارة العملاء (`crm/`) ونظام إدارة المخزون (`inventory/`). الصفحات مخفية عن محركات البحث.

### ربط البوابة بدومين المعرض (staff.ruwwadaletemad.com)
1. عند الجهة المسجّل عندها الدومين (إدارة DNS)، أضف سجلًا جديدًا:
   - النوع: **CNAME** — الاسم/Host: **staff** — القيمة/Target: **mustafa999bilal-jpg.github.io** — TTL: الافتراضي.
2. في GitHub: المستودع ← **Settings** ← **Pages** ← **Custom domain** اكتب `staff.ruwwadaletemad.com` واضغط **Save**، ثم بعد تفعيل الشهادة علّم على **Enforce HTTPS** (قد يأخذ من دقائق لساعات).
3. بعدها تصبح الروابط: `https://staff.ruwwadaletemad.com/crm/` و `https://staff.ruwwadaletemad.com/inventory/`، والروابط القديمة على github.io تتحول لها تلقائيًا.
4. حدّث **Site URL** و **Redirect URLs** في مشاريع Supabase للروابط الجديدة.

- `index.html` — موقع المعرض مع حاسبة التمويل.
- `inventory/` — **نظام إدارة المخزون** (لوحة تحكم داخلية للموظفين).
- `crm/` — **نظام إدارة العملاء** (مستقل تمامًا عن المخزون: رابط، دخول، وقاعدة بيانات منفصلة).

## نظام إدارة المخزون

افتح `inventory/index.html` (أو `/inventory/` على GitHub Pages). يعمل بالكامل في المتصفح بدون سيرفر.

**المزايا**
- لوحة تحكم: قيمة المخزون، الربح المتوقع، مبيعات الشهر، متوسط عمر المخزون، مخطط مبيعات 6 أشهر، وتنبيهات ذكية (سيارات متقادمة، حجوزات منتهية، هوامش منخفضة، صيانة متأخرة).
- السيارات: إضافة/تعديل/حذف، بحث وفلترة وترتيب، رقم مخزون تلقائي، منع تكرار رقم الهيكل (VIN)، سجل زمني لكل سيارة.
- دورة حياة السيارة: في الطريق ← متاحة ← محجوزة (بعربون وتاريخ انتهاء) ← مباعة، مع الصيانة والنقل بين الفروع.
- المبيعات: فاتورة ضريبية قابلة للطباعة (ضريبة القيمة المضافة)، طرق الدفع وجهات التمويل، إلغاء بيع / مرتجع.
- المصاريف: تُحمَّل على تكلفة السيارة وتنعكس على صافي الربح.
- الموردون، سجل حركات كامل (تدقيق)، تقارير (أعمار المخزون، الفروع، أداء الماركات والبائعين).
- تصدير Excel (CSV)، طباعة كشف جرد وبطاقة سعر السيارة، نسخ احتياطي واستيراد.

- تسجيل دخول للموظفين بصلاحيتين (مدير / موظف)، وقاعدة بيانات مشتركة تتحدث لحظيًا على كل الأجهزة.

### وضعا التشغيل
- **بدون قاعدة بيانات (الوضع المحلي):** إذا كان `inventory/config.js` فارغًا، تُحفظ البيانات في متصفح الجهاز فقط وبدون تسجيل دخول.
- **مع قاعدة بيانات (Supabase):** بعد تعبئة `config.js` يطلب النظام تسجيل الدخول، وكل الموظفين يعملون على نفس البيانات.

### ربط قاعدة البيانات (مرة واحدة — حوالي 10 دقائق)
1. أنشئ حسابًا ومشروعًا مجانيًا على [supabase.com](https://supabase.com) (اختر أقرب منطقة، واحفظ كلمة مرور قاعدة البيانات).
2. من **SQL Editor ← New query** الصق محتوى [`inventory/supabase/schema.sql`](inventory/supabase/schema.sql) واضغط **Run**.
3. **مباشرةً بعدها** من **Authentication ← Users ← Add user ← Create new user**: أدخل بريدك وكلمة مرور وفعّل **Auto Confirm User**. أول حساب يُنشأ يصبح **المدير** تلقائيًا.
4. من **Authentication ← Sign In / Providers ← Email**: أوقف **Confirm email** (موصى به حتى يدخل الموظف مباشرة)، واترك **Allow new users to sign up** مفعّلًا — هذا مطلوب لإضافة الموظفين من داخل النظام، وأي حساب يُنشأ من خارج النظام يبقى موقوفًا بلا أي صلاحية حتى يفعّله المدير.
5. من **Authentication ← URL Configuration**: اجعل **Site URL** رابط صفحة النظام (مثلًا `https://<اسم-المستخدم>.github.io/desktop-tutorial/inventory/`) — يُستخدم في روابط "نسيت كلمة المرور".
6. من **Project Settings ← API Keys** انسخ **Project URL** والمفتاح العام (**anon public** أو **publishable**) وضعهما في `inventory/config.js`. هذا المفتاح آمن للنشر؛ لا تضع أبدًا مفتاح **service_role / secret**.
7. افتح النظام وسجّل الدخول بحساب المدير، ثم أضف الموظفين من صفحة **الموظفون**.

### الصلاحيات (تُطبَّق داخل قاعدة البيانات نفسها، وليس في الواجهة فقط)
| | مدير | موظف |
|---|---|---|
| عرض المخزون والمبيعات والتقارير | ✓ | ✓ |
| إضافة/تعديل سيارة، حجز، بيع، مصروف، نقل | ✓ | ✓ |
| حذف سيارة/مصروف/مورد، إلغاء بيع | ✓ | ✗ |
| الإعدادات، الاستيراد، المسح، البيانات التجريبية | ✓ | ✗ |
| إدارة الموظفين | ✓ | ✗ |

- سجل الحركات لا يمكن تعديله أو حذفه من أي موظف، ويُسجَّل معه معرّف المستخدم من الخادم.
- لا يمكن بيع نفس السيارة مرتين حتى لو ضغط موظفان "بيع" في نفس اللحظة، ولا تكرار رقم الهيكل.
- أرقام المخزون والفواتير تصدر من قاعدة البيانات بالتسلسل بدون تكرار.
- لا يمكن إلغاء صلاحية آخر مدير في النظام.


## نظام إدارة العملاء (`crm/`)

افتح `crm/index.html` (أو `/crm/` على GitHub Pages). نظام مستقل لمتابعة العملاء من أول رسالة من الإعلان حتى البيع.

**رحلة العميل (مراحل البيع)**
جديد ← تم التواصل ← مؤهل مبدئيًا ← حسبة مبدئية مرسلة ← بانتظار الأوراق ← تم استلام الأوراق ← تم رفع الطلب للبنك ← وصلت موافقة البنك ← تفاوض نهائي ← **تم البيع** أو **مغلق مع السبب**.
عملاء الكاش يتخطون مراحل البنك تلقائيًا.

**المزايا**
- **مهام اليوم:** الصفحة الرئيسية لكل مندوب — العملاء الجدد (مع عدّاد منذ وصول العميل)، المتابعات المتأخرة، مواعيد اليوم، والعملاء بلا موعد.
- **تسجيل نتيجة التواصل:** رد / لم يرد / واتساب / زيارة، ثم اختيار الموعد القادم بضغطة (بعد ساعتين، غدًا، بعد يومين...). عند "لم يرد" يقترح النظام الموعد التالي ويقترح الإغلاق بعد عدد محاولات محدد.
- **التأهيل التلقائي** بنفس قواعد ملف الإكسل (الحد الأدنى للراتب، راتب المؤهل، نسبة الالتزامات، الأوراق، طريقة الشراء) مع حساب القسط الأقصى وأقصى سعر سيارة.
- **حسبة مبدئية** وإرسالها للعميل على واتساب، و**قوالب واتساب** جاهزة قابلة للتعديل.
- **قائمة أوراق التمويل** لكل عميل، وينتقل العميل تلقائيًا للمرحلة التالية عند اكتمالها.
- **لوحة المراحل** بالسحب والإفلات + جدول بالفلاتر، وتنبيه بالأرقام المكررة.
- **التقارير:** قمع المبيعات، سرعة الرد، أداء مصادر الإعلانات والموظفين، أسباب الإغلاق، جودة العملاء، والأداء الشهري.
- **استيراد ملف الإكسل الحالي:** من Google Sheets افتح ورقة "سجل الليدز" ← ملف ← تنزيل ← CSV، ثم في النظام: العملاء ← استيراد من الإكسل. الاستيراد آمن للتكرار (يتخطى العملاء المستوردين مسبقًا).

**ربط قاعدة البيانات وتسجيل الدخول:** نفس خطوات نظام المخزون أعلاه، لكن بمشروع Supabase **منفصل**، وملف قاعدة البيانات [`crm/supabase/schema.sql`](crm/supabase/schema.sql)، والمفاتيح في `crm/config.js`، و Site URL هو رابط `/crm/`.
